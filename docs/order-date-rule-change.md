# 기획 대비 변경: 수주일·실제 납기 기준

## 변경 이유

실제 업무 순서가 **견적 → 수주 → 발주 → 납품 → 계산서**이고, 발주서에 적힌 발주일자가 수주 시점이기 때문입니다. 기존의 ‘발주서를 전달받은 날’ 기준은 문서상 발주일과 달라질 수 있어 수주 집계 월과 실제 납기를 왜곡할 수 있습니다.

## 변경 전후

- 기존: 수주일은 발주서 전달일 또는 팩스·스캔 수신일 우선. 실제 납기는 매출일(계산서 발행일)에서 수주일을 뺌.
- 변경: 발주서에 **발주일자·발주일**이 명시되면 이를 수주일로 기록. 그 항목이 없고 **작성일만** 있으면 작성일을 발주일자로 보고 수주일로 기록. 어느 것도 없을 때만 담당자님께 수주일을 확인받음. 수신일만으로 수주일을 추정하지 않음. 도장 회신 견적서도 같은 우선순위 적용.
- 변경: 실제 납기(일)는 **계산서 발행일(납품 완료 확인일) − 발주일(수주일)**. 예: `2026-10-08`부터 `2026-11-02`까지 25일.
- 구현: 발주 입력 JSON의 `order_document_date`에는 발주일자·발주일을, 그것이 없으면 작성일을 넣어 CSV `order_date`에 기록. 날짜 항목이 모두 없을 때만 담당자님이 확인한 수주일을 기존 호환 필드 `received_date`로 입력. `received_date`는 자동 수신일 추정용이 아님. 계산서 발행일은 CSV `invoice_date`와 품목별 `delivery_date`에 기록하며 `lead_days`는 두 날짜의 차이. CSV 열 구조는 변경하지 않음.

## 기존 자료에 미치는 영향

가상 `data/ledger.csv` 40건과 `demo/answer_key.csv`로 연결된 정상 발주 PDF를 **읽기 전용**으로 대조했습니다. 발주일자(`발주일자:`)가 명시된 17건에서 대장 `order_date`와 다른 건은 **0건(견적번호 없음)**입니다. 발주일자 없이 **작성일만** 적힌 10건도 새 기준에 따라 모두 대조했고, **차이 0건(견적번호 없음)**입니다. 즉 날짜가 명시된 발주서 27건 중 불일치는 0건입니다. 두 날짜가 없는 도장 회신 5건과 미발주 8건은 문서상 발주일자·작성일 비교 대상이 아닙니다. 기존 40건의 `order_date`는 수정하지 않았으며, 도장 회신 5건의 과거 수주일도 소급 확정하지 않았습니다. 이 5건의 날짜를 새 기준으로 재확정하려면 담당자님 확인이 필요합니다.

기존 시연용 정답표·PDF·`data/` 대장은 수정하지 않습니다. 신규 입력부터 우선순위를 적용합니다.
